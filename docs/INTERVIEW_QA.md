## 一、开场自我介绍（30 秒版）

> "我在 TikTok Shop 马来西亚站做类目运营实习时，发现 Flash Sale 选品完全靠人工在 Excel 里拍脑袋打分——同一个商品不同运营打分都不一样，每周复盘要花两小时做透视表，卖家报名信息经常缺字段、要一封封催。我把这个痛点写成了一份 PRD，并且更进一步，**把它实现成了一个可运行的 Python 工具**，用 40% GMV + 30% 转化率 + 20% 折扣力 + 10% 卖家表现的加权评分模型做客观选品，用规则引擎自动生成周报，用校验器自动生成卖家催办消息。现在这个项目在 GitHub 上开源，有 10 个单元测试、CI 自动跑，任何人都能 `python demo.py` 一键跑通。"

### Q2. 评分模型为什么是 40/30/20/10 这个权重？

**回答要点：**

- 权重来自**运营实际经验**：历史 GMV 直接反映商品赚钱能力，给最大权重（40%）；转化率反映商品在平台上的承接能力（30%）；折扣力决定 Flash Sale 的吸引力，但过高折扣伤毛利，所以不是越高越好（20%，且封顶 60% 用 sigmoid 递减，避免极端折扣误导）；卖家表现（评分 + 响应速度）影响履约和服务体验（10%）。
- **可解释性**：这是给运营团队用的工具，权重要能讲得清、能调。代码里 `SCORE_WEIGHTS` 是公开常量，`FlashSaleScorer(weights=自定义)` 一行就能改——这体现你考虑了"业务方要能自己调参"。
- 可以补充：真实业务里权重应该用历史大促数据回归/主观打分校准来定，这是可改进方向（体现你有迭代思维）。

---

### Q3. 洞察报告是怎么"自动生成"的？用的是什么 AI？

**回答要点（诚实 + 技术细节）：**

- 项目用**规则引擎**实现，不依赖外部 LLM API——这是刻意的设计决策：第一，本地可运行、可复现、可测试；第二，模拟了真实生产里"AI 生成 → 人工验证"的工作流，输出同样的结构化报告。
- 具体逻辑：百分位阈值（TOP 75 分位 + BOTTOM 25 分位）找头部/尾部商品；规则匹配成功因子（转化高于中位数、折扣≥35%、评分≥4.5）和问题诊断（转化<4%、折扣<25%、评分<4.3、响应率<80%）；类目分析按 GMV/转化分档评级（Excellent/Good/Average/Below Average）。
- 诚实补充："如果接入 LLM，报告语言会更自然，但规则引擎的优势是**每次输出可复现、可测试**——运营敢用你的结论。"

### Q4. 这个工具实际部署上线了吗？业务效果怎么样？

**回答要点（诚实，不编数据）：**

- 实习期间我完成的是**产品方案 + 核心逻辑实现**。工具逻辑在我的实习观察和方案验证范围内，没有在实习期内部署上线。
- 但要说清楚**为什么值得做**（这是你能算的账）：
  - 选品效率：人工按维度打分，1-2 天 → 工具 1 小时（全量计算 + 自动排序）。
  - 一致性：消除"同一商品不同运营打分不同"的主观偏差，决策可追溯。
  - 周报：2 小时/周 → 秒级生成。
- **不要说任何编造的上线数据**。面试官追问时承认"这是 MVP 级别实现 + 完整 PRD，业务验证是下一步"——这比吹牛更能赢信任。

### Q5. 项目里最难的部分是什么？你怎么解决的？

**回答要点（选一个有细节的故事）：**

**候选 A（数据/权重）：** 难点是怎么把"运营拍脑袋"变成可量化的公式。解决：先拆解运营选品时会看的维度（GMV、转化、折扣、卖家），再定义每个维度的量化和归一化方法（min-max 归一化到 0-100；折扣用封顶 + 线性递减避免极端折扣误导）。

**候选 B（洞察的"原因分析"）：** 难点是让机器输出"为什么好/为什么差"，而不只是排名。解决：为头部商品定义成功因子匹配规则（转化高于中位数、折扣到位、卖家评分高），为尾部商品定义问题诊断规则，让结论可解释、可行动。

**候选 C（工程化）：** 难点是让"能跑的脚本"变成"可信的工程"。解决：补单元测试（10 个用例覆盖评分、排序、标签、异常）、写 demo.py、配 GitHub Actions CI，让项目"每次改动都被自动验证"。

### Q6. 如果再给你两周，你会怎么改进？

**回答要点（体现迭代思维，选 2-3 条）：**

1. **接 LLM 生成洞察**：规则引擎 → 调用 LLM API 生成更自然的报告文案，同时保留规则做校验兜底。
2. **权重校准**：用历史大促数据（GMV、转化、退货率）回归校准权重，替代经验值。
3. **更多运营场景**：加库存预警、活动后复盘、竞品折扣监控。
4. **可视化**：加一个简单 Web 面板（Streamlit），让运营不用命令行。
5. **数据接口**：对接真实数据源（风神/平台报表 API），替换示例 CSV。

### Q7. 这个项目和"AI 运营"方向有什么关系？你理解 AI 在电商运营里怎么落地？

**回答要点（拔高视野）：**

- AI 在运营的落地不是"一个聊天机器人"，而是**把可重复、有规则、耗人力的流程自动化**：选品打分、报告生成、信息校验、消息触达。
- 这个项目正好是这三个场景的最小实现：**决策自动化**（评分模型）、**内容自动化**（洞察报告）、**流程自动化**（注册检查 + 催办）。
- 运营的 AI 工具要过"信任关"：可解释（为什么打这个分）、可验证（测试覆盖）、可控（人能调权重要覆盖）。我的项目把这三条都做了。
- 这和你求职的策略运营/商业化运营/电商运营岗位高度契合：**用数据和工具思维解决运营效率问题**。
